# Data model

The canonical contract is **schema v2.0**, defined in [`src/domain/schema.ts`](../src/domain/schema.ts) and published as JSON Schema in [`schemas/`](../schemas/), which is generated by `npm run schemas`. This page explains the model. The code is authoritative.

## Snapshot

A snapshot is one collection of evidence at a point in time.

| Field                                           | Meaning                                                                                                                     |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion`                                 | `"2.0"`                                                                                                                     |
| `snapshotId`, `collectedAt`, `environmentLabel` | Identity and time of collection                                                                                             |
| `dataOrigin`                                    | `fixture`, `local_discovery`, or `import`. **Fixture snapshots require `fixtureNotice`**, which the UI shows on every page. |
| `nodes[]`, `edges[]`                            | The graph                                                                                                                   |
| `connectorRuns[]`                               | What each source did: status, read-only flag, data categories, required privileges, coverage, blind spots, and errors       |

## Nodes

`{ id, type, label, description?, trustBoundaryId?, attributes, provenance[≥1] }`

- **IDs** match `^[a-z][a-z0-9_-]*:\S+$`, for example `agent:cursor` or `cred:github-pat`. They are stable across runs.
- **Types:** `UserIdentity`, `Application`, `Process`, `Agent`, `MCPServer`, `Tool`, `OAuthGrant`, `CredentialReference`, `CloudRole`, `Resource`, `Permission`, `Policy`, `TrustBoundary`.
- **Agent ≠ Application.** The application `HOSTS` the agent, and the agent reaches only what its connections give it.
- **Attributes** are values of type string, number, boolean, or string[]. Analysis reads only the keys in [`attributeKeys.ts`](../src/domain/attributeKeys.ts), through typed accessors:

| Key                              | Values                                                                        | Used by                                |
| -------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------- |
| `sensitivity`                    | low, moderate, high, critical                                                 | Impact ranking, finding severity       |
| `scopeBreadth`                   | narrow, broad, admin                                                          | `broad-credential-scope` rule          |
| `networkEgress`                  | boolean                                                                       | Exfiltration hypotheses                |
| `enforcementState`               | enforced_verified, monitor_only, advisory, external_declared, not_enforceable | Control semantics (required on Policy) |
| `controlEffect`                  | deny, require_approval, monitor                                               | Control semantics                      |
| `packageSource`, `versionPinned` | npm, pypi, docker, … and boolean                                              | `unpinned-registry-mcp-server` rule    |
| `permissionKind`                 | e.g. `os_privacy`                                                             | `unknown-os-privacy-permission` rule   |

## Edges

`{ id, type, from, to, assertion, confidence, lifecycle, inferenceRule?, requiresAction?, scopes?, conditions[], attributes, provenance[≥1] }`

| Edge type                                                         | Propagation            | Meaning: "`from` … `to`"                             |
| ----------------------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| `RUNS_AS`                                                         | forward                | runs as (an identity)                                |
| `HOSTS`                                                           | forward                | hosts (an agent or process)                          |
| `CONNECTS_TO`                                                     | forward                | can send requests to                                 |
| `EXPOSES_TOOL`                                                    | forward                | exposes tool                                         |
| `AUTHENTICATES_WITH`                                              | forward                | authenticates with (a credential reference or grant) |
| `HOLDS_CREDENTIAL_REFERENCE`                                      | forward                | holds a reference to                                 |
| `GRANTS_SCOPE`                                                    | forward                | holds permission                                     |
| `ASSUMES_ROLE`                                                    | forward                | can assume role                                      |
| `CAN_READ`, `CAN_WRITE`, `CAN_DELETE`, `CAN_EXECUTE`, `CAN_ADMIN` | forward, grants action | can read, write, delete, execute, or administer      |
| `DELEGATES_TO`                                                    | forward                | delegates to                                         |
| `TRUSTS`                                                          | **reverse**            | trusts (compromising `to` affects `from`)            |
| `REACHES`                                                         | forward                | has network reach to                                 |
| `CONTROLLED_BY`                                                   | none                   | is governed by (a Policy)                            |

- **assertion:** observed, declared, inferred, hypothetical, or unknown. See [ADR 0004](./adr/0004-assertions-provenance-and-findings.md).
- **confidence:** high, medium, or low. Independent of the assertion.
- **lifecycle:** active or revoked. Revoked edges are never followed.
- **conditions:** each is `{ description, state: holds | does_not_hold | unresolved }`.
- **requiresAction:** required on propagating edges that leave a Resource, for example "write access to the repo is needed to use its deploy role".

## Provenance

`{ connectorId, evidenceRef, observedAt, collectionMethod }`

- **evidenceRef** points to _where_ the evidence is, such as a config path and key, or a provider API object. It never holds the value.
- **Freshness** is computed at analysis time from the newest `observedAt`, so it is never stale in storage.

## Findings (derived, not stored in the graph)

Defined in [`src/domain/finding.ts`](../src/domain/finding.ts), with the published schema in [`schemas/finding.schema.json`](../schemas/finding.schema.json):

`{ id, ruleId, ruleVersion, title, severity, confidence, status, affectedEntityIds, pathEdgeIds, rationale, assumptions, evidenceRefs, remediation[≥1], relatedControlIds, detectedAt, evidenceIsStale }`

## What is never stored

- Secret values: tokens, keys, passwords, cookies, private keys, URLs with embedded credentials. Snapshots containing them are rejected, and the error reports the location and pattern, never the value.
- Credential references are stored instead: env var _names_, Keychain service and account labels, vault URIs such as `op://Vault/Item/field`.

## Mapping from the starter v1.0 schema

The starter files (`docs/archive/starter/schemas/*.json`, `docs/archive/starter/examples/sample-graph.json`) are kept as historical input.

### Fields

| v1.0 (`graph.schema.json`)                                        | v2.0                                                                                                                   | Note                                                                                                      |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `schema_version`, `snapshot_id`, `collected_at`, `environment_id` | `schemaVersion`, `snapshotId`, `collectedAt`, `environmentLabel`                                                       | camelCase. v2 adds `dataOrigin`, `fixtureNotice`, and `connectorRuns`.                                    |
| node `name`                                                       | node `label`                                                                                                           |                                                                                                           |
| node and edge `source_id`, `observed_at`, edge `evidence_ref`     | `provenance[]` of `{ connectorId, evidenceRef, observedAt, collectionMethod }`                                         | Multiple sources per fact, so corroboration is possible                                                   |
| node `secret_value` (schema forbids it: `not: {}`)                | No field. The whole snapshot is secret-scanned.                                                                        | v2 rejects secret-shaped values anywhere, not only in one named field                                     |
| edge `status`: observed, inferred, stale, unknown, revoked        | `assertion` (observed, declared, inferred, hypothetical, unknown) + `lifecycle` (active, revoked) + computed freshness | v1 mixed three separate ideas into one field. Staleness depends on `asOf`, so it is computed, not stored. |
| edge `confidence`                                                 | edge `confidence`                                                                                                      | Unchanged values (high, medium, low)                                                                      |
| edge `conditions`                                                 | `conditions[]` of `{ description, state }`                                                                             | The state makes unresolved conditions explicit                                                            |

### Node types

| v1.0                                                         | v2.0                                                          |
| ------------------------------------------------------------ | ------------------------------------------------------------- |
| `agent`                                                      | `Agent` (hosted by an `Application`)                          |
| `identity`                                                   | `UserIdentity`                                                |
| `mcp_server`, `tool`, `resource`, `policy`, `trust_boundary` | `MCPServer`, `Tool`, `Resource`, `Policy`, `TrustBoundary`    |
| `credential_ref`                                             | `CredentialReference`, plus `OAuthGrant` for delegated grants |
| `action`                                                     | `Permission` node and/or `CAN_*` edges                        |
| `integration`                                                | **Deferred** until a connector produces it                    |
| —                                                            | New: `Application`, `Process`, `CloudRole`                    |

### Edge types

| v1.0                                                | v2.0                                                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `CONNECTS_TO`, `EXPOSES_TOOL`, `AUTHENTICATES_WITH` | Same names                                                                                                   |
| `USES_IDENTITY`                                     | `RUNS_AS`                                                                                                    |
| `RUNS_IN`                                           | `HOSTS` (direction reversed: the host points to what it hosts)                                               |
| `HAS_POLICY`                                        | `CONTROLLED_BY`, with the target Policy's `enforcementState`                                                 |
| `GRANTS_ACTION`                                     | `GRANTS_SCOPE` (to a Permission) and `CAN_READ`, `CAN_WRITE`, `CAN_DELETE`, `CAN_EXECUTE`, `CAN_ADMIN`       |
| `CAN_ACCESS`                                        | One of the `CAN_*` edges, because access must name the action                                                |
| `CROSSES_BOUNDARY`                                  | **Removed as an edge.** Boundary crossings are derived from each node's `trustBoundaryId`.                   |
| `OWNS`                                              | **Deferred**                                                                                                 |
| `DERIVED_FROM`                                      | `inferenceRule` on the inferred edge                                                                         |
| —                                                   | New: `HOLDS_CREDENTIAL_REFERENCE`, `ASSUMES_ROLE`, `DELEGATES_TO`, `TRUSTS` (reverse propagation), `REACHES` |

### Types suggested by the permission-graph skill but deferred

The skill lists `MCPClient`, `Integration`, `IdentityProvider`, `Group`, and `Capability`, and says "do not create every entity type speculatively". v2 follows that. `MCPClient` is modeled as an `Application` that `HOSTS` an `Agent`. The others will be added when a connector produces them. `Finding` is deliberately **not** a graph node ([ADR 0004](./adr/0004-assertions-provenance-and-findings.md)).
